# Algebraic Solver Implementation Plan

## Architecture Overview

```
SSA Equations
    │
    ▼
┌─────────────────────┐
│ Polynomial Extractor │  Extract polynomial equations from SSA
│ (exprt → poly_ring)  │  Identify equational fragment
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ Gröbner Basis Engine │  Compute strong Gröbner basis over Z_{2^d}
│ (poly_ring → result) │  Check if 1 ∈ ideal (UNSAT)
└─────────┬───────────┘
          │
          ├── UNSAT → done (no bit-blasting needed)
          │
          ├── SAT → extract witness, verify against residual
          │         (Level 3: CEGAR with bit-blasting)
          │
          └── UNKNOWN → fall through to bit-blasting (comba-cs)
```

## Phase 1: Polynomial Ring Library

### File: `src/solvers/algebraic/poly_ring.h`

```cpp
// Polynomial over Z_{2^d}[x_1, ..., x_n]
// Represented as a map from monomials to coefficients.

// A monomial is a product of variables with exponents.
// E.g., x_1^2 * x_3 is represented as {1: 2, 3: 1}.
// We use a sorted vector of (var_index, exponent) pairs.
struct monomialt {
  std::vector<std::pair<std::size_t, unsigned>> vars; // sorted by var_index
  // Comparison for monomial ordering (graded reverse lex)
  bool operator<(const monomialt &other) const;
  unsigned total_degree() const;
  monomialt operator*(const monomialt &other) const;
  bool divides(const monomialt &other) const;
  monomialt quotient(const monomialt &divisor) const;
};

// Coefficient: integer mod 2^d, stored as mp_integer
// (CBMC already has mp_integer in util/mp_arith.h)
using coefft = mp_integer; // all arithmetic mod 2^d

// A polynomial is a sum of (coefficient, monomial) pairs.
// Stored sorted by monomial ordering (leading term first).
class polynomialt {
public:
  std::size_t bitwidth; // d in Z_{2^d}
  std::vector<std::pair<coefft, monomialt>> terms; // sorted, leading first

  // Arithmetic mod 2^d
  polynomialt operator+(const polynomialt &other) const;
  polynomialt operator-(const polynomialt &other) const;
  polynomialt operator*(const polynomialt &other) const;
  polynomialt operator*(const coefft &scalar) const;

  // Leading term
  const monomialt &leading_monomial() const;
  coefft leading_coefficient() const;

  // Reduce mod 2^d
  void normalize();

  bool is_zero() const;
  bool is_constant() const;
  coefft constant_value() const;
};
```

### Key operations needed:
- `mp_integer mod_2d(mp_integer val, unsigned d)` — reduce mod 2^d
- `mp_integer inverse_mod_2d(mp_integer a, unsigned d)` — multiplicative
  inverse of odd a mod 2^d (extended Euclidean)
- `mp_integer gcd_with_2d(mp_integer a, unsigned d)` — for divisibility checks

CBMC already has `mp_integer` in `src/util/mp_arith.h` with full
arithmetic. We just need modular reduction and inverse.

## Phase 2: Strong Gröbner Basis Algorithm

### File: `src/solvers/algebraic/groebner.h`

```cpp
class strong_groebner_basist {
public:
  // Compute strong Gröbner basis of the ideal generated by polys
  // Returns true if 1 is in the ideal (UNSAT)
  bool compute(std::vector<polynomialt> &polys);

private:
  // S-polynomial of f and g
  polynomialt s_polynomial(const polynomialt &f, const polynomialt &g);

  // Strong reduction: reduce f by the basis
  polynomialt strong_reduce(const polynomialt &f,
                            const std::vector<polynomialt> &basis);

  // The key difference from classical Gröbner bases:
  // In Z_{2^d}, the leading coefficient may not be a unit.
  // Strong reduction handles this via the "strong" criterion:
  // if lc(f) = 2^k * u where u is odd, we can:
  //   1. Reduce by a basis element whose lc divides lc(f)
  //   2. Or multiply f by 2^(d-k) to kill the leading term
  //      (since 2^k * 2^(d-k) = 2^d = 0 mod 2^d)
};
```

### The Buchberger-like algorithm for Z_{2^d}:
```
Input: F = {f_1, ..., f_k} ⊂ Z_{2^d}[x_1, ..., x_n]
Output: Strong Gröbner basis G

G := F
pairs := all pairs (f_i, f_j) from G
while pairs is not empty:
    (f, g) := pick a pair from pairs
    s := s_polynomial(f, g)
    r := strong_reduce(s, G)
    if r ≠ 0:
        add r to G
        add all pairs (r, g') for g' in G to pairs
    // Also handle the "2-multiples":
    // For each f in G with lc(f) = 2^k * u (k > 0):
    //   h := 2^(d-k) * f  (kills leading term, may reveal new info)
    //   r := strong_reduce(h, G)
    //   if r ≠ 0: add r to G
if any g in G is a nonzero constant: return UNSAT
return SAT/UNKNOWN
```

## Phase 3: Polynomial Extractor

### File: `src/solvers/algebraic/poly_extract.h`

Extract polynomial equations from CBMC's expression trees.

```cpp
class poly_extractort {
public:
  // Convert an exprt to a polynomial (if possible)
  // Returns nullopt if the expression contains non-polynomial ops
  // (bitwise AND/OR/XOR, shifts, division, comparisons)
  std::optional<polynomialt> to_polynomial(const exprt &e, unsigned bitwidth);

  // Extract equational constraints from a set of SSA equations
  // Returns the polynomial equations and the residual (non-polynomial) part
  struct extraction_resultt {
    std::vector<polynomialt> equations;  // polynomial part
    std::vector<exprt> residual;         // non-polynomial part
  };
  extraction_resultt extract(const std::vector<exprt> &constraints);

private:
  // Variable mapping: SSA symbol → polynomial variable index
  std::map<irep_idt, std::size_t> var_map;
  std::size_t next_var_index = 0;

  std::size_t get_var_index(const irep_idt &name);
};
```

### What can be converted to polynomials:
- `ID_plus` → polynomial addition
- `ID_mult` → polynomial multiplication
- `ID_minus` → polynomial subtraction
- `ID_unary_minus` → negation (multiply by -1 mod 2^d)
- `ID_symbol` → polynomial variable
- `ID_constant` → polynomial constant
- `ID_typecast` (widening/narrowing) → mod 2^d adjustment
- `ID_equal` (in assertions) → f - g = 0

### What CANNOT be converted (residual):
- `ID_bitand`, `ID_bitor`, `ID_bitxor` — bitwise ops
- `ID_shl`, `ID_lshr`, `ID_ashr` — shifts (EXCEPT constant shifts = multiply by 2^k)
- `ID_div`, `ID_mod` — division
- `ID_lt`, `ID_le`, `ID_gt`, `ID_ge` — inequalities
- `ID_if` — conditional expressions

## Phase 4: Integration into CBMC

### Option A: Preprocessing pass (Level 2)

Add to `boolbvt::set_to()` or `symex_target_equationt::convert()`:
1. Collect all equations
2. Extract polynomial part
3. Run Gröbner basis
4. If UNSAT → report immediately
5. If SAT/UNKNOWN → proceed with bit-blasting

### Option B: Decision procedure (Level 3, keeps door open)

Create `algebraic_solvert` that wraps `bv_pointerst`:
1. Collect equations in `set_to()`
2. On `dec_solve()`:
   a. Extract polynomial part
   b. Run Gröbner basis on polynomial part
   c. If UNSAT → done
   d. If SAT → get algebraic witness, check residual via bit-blasting
   e. If residual violated → add violated constraint, iterate (CEGAR)

Option B is preferred because it keeps Level 3 open and integrates
cleanly with the existing solver architecture.

## Implementation Order

1. **poly_ring** — polynomial representation and arithmetic over Z_{2^d}
   - monomial ordering, addition, multiplication, normalization
   - multiplicative inverse mod 2^d
   - ~200 lines

2. **groebner** — strong Gröbner basis algorithm
   - S-polynomial, strong reduction, Buchberger loop
   - ~300 lines

3. **poly_extract** — expression → polynomial conversion
   - Handle ID_plus, ID_mult, ID_minus, ID_symbol, ID_constant
   - Identify and separate residual (non-polynomial) constraints
   - ~200 lines

4. **Integration** — hook into boolbvt::set_to() as preprocessing
   - Collect equations, run Gröbner basis, report UNSAT or fall through
   - ~100 lines

5. **Testing** — verify on our benchmark suite
   - comm_16 (intermediate vars): should be solved algebraically
   - assoc_8, distrib_8: should be solved algebraically
   - overflow_detect_16: should fall through (has inequality)
   - keyed_hash: should fall through (has XOR)

## Complexity Considerations

- Gröbner basis computation is doubly exponential in the worst case
- But for our benchmarks (2-4 variables, degree 2-3), it's fast
- The key optimization: if the basis computation exceeds a time/step
  limit, fall through to bit-blasting (no correctness impact)
- Song et al. report solving 2466 benchmarks in <10s each
